Here’s Why Wearing Many Hats is Important for a Software Developer

A reflection on my professional work experience as a software developer and the value I’ve found in not letting traditional roles define me

I recently read an article that introduced me to the concept of the T-shaped developer.

The author talks about the importance of having specialist and generalist knowledge as a software developer. Such a person might be called

A Jack of all trades, master of some

This resonated with me as it spoke to my personal experiences of working as a software developer over the last 3 years. During my time at Skynamo, I’ve had the pleasure of wearing a bunch of different hats.

  • I was a pure frontend developer when I helped create our design system which used Vue 3 and Tailwind CSS.
  • I was a backend-frontend developer when I helped create a caching layer for our customers’ analytics dashboard. This required me to work heavily with API responses, manipulate data to conform to all the dashboard tile requirements, determine when to resync the data from the various services when I’ve determined the cache was stale and optimise all this so the dashboard response isn’t as slow a tortoise.
  • I’ve stunted as a backend developer here and there when I wrote an API server for one of the projects we were working on. I now regularly maintain the analytics service responsible for returning around 80% of the data needed by the analytics dashboard.

Aside from these more traditional roles, I have also worked in other areas.

One of these is the Skynamo Power BI connector. This is a plugin for Microsoft Power BI which allows customers to easily download their data from the analytics service into Power BI for creating even crazier dashboards. I regularly maintain the plugin and make updates to it when needed.

Recently, I’ve also been working with the integrations team where I’ve helped in the creation of an integration service that pulls data from various accounting software and places it into Skynamo. At present, I’ve done this for Xero, Sage Pastel Partner ZA, and Sage Intacct with more accounting systems to come. This is a pretty cool project because it combines so many areas of programming into one.

For example, Sage Pastel Partner ZA is a program mostly designed to work on a local machine or a private server. This means we had to create our own Windows service that ran on the machine which periodically pulls data from the local database to upload to Skynamo. For obvious reasons, we wanted the adding of the service to be as easy as possible which led to the need to create our own installer for the service also. Side tangent here. You’d think Microsoft would make it easy for you to write a fairly straightforward installer for their own operating system 🤣🤣🤣. I thought web dev is a mess but honestly, I’m now amazed any software works on Windows.

I’ve also helped out in creating the service that received said data from the Windows service and transformed it into a data format which makes sense for Skynamo. All in all, this project required me to learn a bit about developing for Windows(It is so cool seeing your program in the Task Manager services 😎), creating build pipelines, testing Windows programs using virtual machines, backend development of services to interact with streamed data, and hiding all this complexity by building a beautiful non-assuming UI designed by our incredibly talented designer.

So yeah 🤷‍♂️🤷‍♂️. The author wasn’t lying about the importance of having more than one trick up your sleeve. But, you might wonder how you can learn so many different things in one go and the straightforward answer is you don’t. I didn’t know any of these things when I started working at Skynamo. What I did have though was a lot of curiosity and a willingness to learn.

Whilst I won’t say labels like frontend, backend or full stack developer are useless, it's also important for you to understand these are just labels. At the end of the day, the core principles of programming don’t change much. Whether it's the UI components in the front end, the caching layer in the backend-frontend, the server function in the backend, the Windows service on the operating system, or the operating system itself, at the end of the day it's all just code. Code is code and all code is just a bunch of instructions telling the machine to do something. When you think about it from that perspective, you realize how limiting it is for you to think you can never understand what goes on in X thing. It's not that you can’t understand it, you just convinced yourself you can’t.

There is still a lot of merit in going deep into a specific field you are interested in. All I wanted to say is you can actually go deep in many fields and chances are pretty high you’ll need to if you want to keep challenging yourself. So yeah, I really enjoyed the article because it helped formalize a concept I wasn’t aware of but I instinctively knew was important. Be a T-shaped developer. I promise its a lot more fun than just sticking to one lane.
